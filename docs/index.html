01架構現況——為什麼是 LangGraph，不是改 n8n

對齊你在 PR#1 跟更早之前的判斷：n8n 是純線性 DAG，做不出「審核退回→重寫」這種迴圈。

Node A 研究 → Node D 創意 → Node B 寫作 → Node C 摘要
⚠ 這是一支純單向 workflow——connections 裡沒有任何一條從審核點打回 Node B 重寫的邊。今天查了 Content Factory v5.0 - Core.json 確認過。

所以「調整 n8n」實際上不是去改這支 workflow，是把「退件重寫」這個迴圈用 LangGraph 另外做出來、驗證能不能動——這正是今天 qoome-iven-voice-spike 在做的事，刻意不碰 n8n、不碰正式編輯台，先在旁路上把機制證明出來。

02今天的實驗記錄（含一次誠實的自我推翻）

照時間順序，每一步都是真的跑出來的結果，不是規劃。

B1 · 語料
建 labeled eval-set
從 personal-wiki 既有著作（忘機書稿 + QB 2021-22 語料）撈 6 個真 Iven Tier-A 短稿範例，配 5 個 slop 負例（3 篇 AI 模仿稿 + 2 篇通用企業模板）。
B2 · 機制
Gate 改 contrastive + judge 分離 + verbatim 否決
Judge 不再單獨打分，改成直接對照 eval-set 的真跡/slop 範例判斷「比較像哪邊」；judge 模型跟 draft 模型分開（避免自我圈選）；另外抓到一個真發現——draft 逐字複製了 prompt 給的舊心法用詞「反套利設計律」，靠加權分數完全看不出來，後來改成硬性否決。
B3 · 校準
拿新 gate 測 eval-set 本身——分不開
Iven 範例分數 0.85–0.95，slop 範例分數 0.0–0.95，兩篇 AI 模仿稿被打到跟真跡一樣高。不管絕對打分還是 contrastive 包裝，判斷依據還是 prompt-only LLM judge，就是同一道牆。

B3.5 → B3.6 · 補測
零成本統計方法「先看似分得開」，控制話題後現形
先試了字元 n-gram 統計距離（零依賴、免 API），第一輪看似分得開（gap +0.073）——但這批 Iven 範例全講忘機/QB，slop 全講 Character.AI 訴訟，懷疑是話題詞彙的假訊號。

用兩篇同話題的 held-out 真實 draft 重測（一篇乾淨過關、一篇有 verbatim 瑕疵），兩篇都被判成「像 slop」——證實第一輪是話題混淆，不是真的風格訊號。回到 B3 的結論：這道牆還在。
